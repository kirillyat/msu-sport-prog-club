# Клуб спортивного программирования ФИИ МГУ

Портал клуба: преподаватель назначает задачи с LeetCode и Codeforces,
система сама видит, кто что решил, ведёт рейтинг и проводит ивенты.

Название и короткая форма настраиваются через `APP_NAME` и `APP_SHORT_NAME`
в `.env` — под другой клуб проект перенастраивается двумя строками.

Один Python-процесс + SQLite в томе. Ни Postgres, ни Kafka, ни Redis, ни отдельного воркера.

---

## Что уже работает

**Студент**
- Вход через Telegram-бота (одноразовый код, без публичного домена).
- Привязка аккаунтов Codeforces и LeetCode с подтверждением владения.
- Вступление в группу по коду от преподавателя.
- Список заданий с прогрессом и дедлайнами, страница задания по задачам.
- **Лента решений**: кто из группы что решил и когда, с привязкой к заданию.
- **Объявления** с обратным отсчётом до старта соревнования и ссылкой на него.
- **Профиль**: баллы и место в рейтинге, прогресс по заданиям, последние решения,
  календарь активности, разбивка по сложности, платформам и темам.
  Кнопка «Обновить результаты» синхронизирует посылки не отходя от страницы.
- Лидерборд по группе и за период.

**Преподаватель**
- Группы с кодом вступления.
- Списки задач: вставляешь ссылки и коды текстом — система сама находит задачи в каталоге.
- Задания группе с дедлайном, матрица `студенты × задачи` с отметками.
- Ивенты с временным окном и своими правилами начисления баллов.
- Объявления клубу или отдельной группе: ссылка на контест, время старта, закрепление.
- Ручные бонусные баллы, управление ролями.
- Лента по всем студентам или по конкретной группе.
- Кнопка принудительной синхронизации в профиле любого студента.
- Поиск по каталогу (11 400 задач Codeforces + 4 055 LeetCode).

**Под капотом**
- Фоновый синкер тянет посылки каждые 10 минут и обновляет каталог раз в сутки.
- Новая задача с только что прошедшего контеста подвяжется к посылкам сама,
  как только попадёт в каталог.
- Интерфейс без внешних зависимостей: иконки — инлайновый SVG-спрайт,
  светлая и тёмная темы по системной настройке, ни одного запроса к CDN.

## Быстрый старт

### Docker (так это живёт в проде)

```bash
cp .env.example .env
docker run --rm -v "$PWD:/w" -w /w python:3.12-slim python -c "import secrets;print('SECRET_KEY='+secrets.token_urlsafe(48))"
```

Полученную строку вставь в `.env` вместо заготовки, туда же — токен бота
и свой telegram id. Затем:

```bash
docker compose up -d --build
```

Открой http://localhost:8000. **Первый вошедший становится преподавателем.**

База лежит в именованном томе `sport-data` и переживает `docker compose down`
и пересборку образа. Миграции применяются при каждом старте контейнера.

> Если `docker compose` не работает как подкоманда, используй отдельный
> бинарник `docker-compose` — команды те же.

Без своего `SECRET_KEY` приложение **осознанно не стартует**: этим ключом
подписываются сессионные куки, и с известным значением любой может войти
под чужим аккаунтом. Сообщение об ошибке скажет, что делать.

### Локально

```bash
python3 -m venv .venv && .venv/bin/pip install -e .
cp .env.example .env          # поставь DEV_LOGIN_ENABLED=true
.venv/bin/alembic upgrade head
.venv/bin/uvicorn app.main:app --reload
```

С `DEV_LOGIN_ENABLED=true` на `/login` появится форма входа по имени —
Telegram-бот для разработки не нужен. **В проде обязательно `false`.**

## Выкатка на сервер

Что нужно на сервере: `git`, `docker`, `docker compose`.

```bash
git clone <адрес репозитория> /srv/sport
cd /srv/sport
cp .env.example .env
python3 -c "import secrets;print('SECRET_KEY='+secrets.token_urlsafe(48))"   # в .env
docker compose up -d --build
```

Сервис слушает `127.0.0.1:8000`. Наружу его отдаёт обратный прокси —
он же выдаёт HTTPS, без которого Telegram-вход через штатный виджет
работать не будет (вход через бота работает и без домена).

Проверка перед боем:

| | |
|---|---|
| `SECRET_KEY` | свой, не из примера |
| `DEV_LOGIN_ENABLED` | `false` |
| `TELEGRAM_BOT_TOKEN` | задан, иначе входа не будет |
| `TEACHER_TELEGRAM_IDS` | твой telegram id |
| `BASE_URL` | внешний адрес с `https://` |
| Порт 8000 | закрыт снаружи, доступен только прокси |

### Обновление

```bash
cd /srv/sport && git pull && docker compose up -d --build
```

### Резервная копия

Простой `cp` файла базы не подходит: при включённом WAL часть транзакций
лежит в `sport.db-wal` и копия может оказаться битой. Правильный способ —
через backup API SQLite, он безопасен на работающем сервисе:

```bash
docker compose exec web python -m app.cli backup /data/backup.db
docker compose cp web:/data/backup.db ./backup-$(date +%F).db
```

Восстановление — положить файл как `sport.db` в том `sport-data`
при остановленном контейнере.

## CI/CD

В `.github/workflows/` лежат два файла. **Gitea Actions читает этот каталог
так же, как GitHub**, поэтому настраивать ничего не нужно — достаточно, чтобы
у Gitea был подключён `act_runner` с меткой `ubuntu-latest`.
Если понадобится развести поведение, скопируй файл в `.gitea/workflows/` —
он будет главнее.

**`ci.yml`** — на каждый push и pull request:

- `ruff` по всему проекту;
- `pytest` (100+ тестов);
- `alembic check` — модели и миграции не разъехались;
- сборка Docker-образа и дымовой тест: контейнер поднимается и отвечает на `/healthz`;
- проверка, что с дефолтным `SECRET_KEY` контейнер отказывается стартовать.

**`deploy.yml`** — выкатка вручную (`workflow_dispatch`). Пока не заданы
секреты, ничего не запускается. Нужные секреты репозитория:

| Секрет | Что это |
|---|---|
| `DEPLOY_HOST` | адрес сервера |
| `DEPLOY_USER` | пользователь ssh |
| `DEPLOY_KEY` | приватный ssh-ключ без пароля |
| `DEPLOY_PATH` | каталог с клоном на сервере |

Выкатка делает резервную копию базы, обновляет код, пересобирает образ
и проверяет `/healthz`. **Откат кода не откатывает схему** — если миграция
уже применилась, возвращайся вперёд, а не назад.

## Свой логотип

Положи файл в `app/static/` — он подхватится автоматически, без правок кода:

| Файл | Куда идёт |
|---|---|
| `logo.svg` / `logo.png` | в шапку и на страницу входа |
| `logo-dark.svg` / `logo-dark.png` | замена для тёмной темы (необязательно) |
| `favicon.png` | иконка вкладки (иначе берётся `logo.*`) |

SVG предпочтительнее — не мылится на ретине. Для PNG бери высоту от 96 px:
в шапке логотип рисуется высотой 24 px, на входе — до 72 px.

**Про тёмную тему.** Один тёмно-синий PNG на тёмном фоне почти не виден.
Либо клади второй файл `logo-dark.*` со светлым вариантом, либо используй
логотип, который читается на обоих фонах.

Если ни одного файла нет, рисуется встроенный знак — силуэт Главного здания
МГУ из того же SVG-спрайта, что и остальные иконки.

Статика запечена в образ, поэтому после добавления файла нужна пересборка:

```bash
docker-compose up -d --build
```

Быстро посмотреть, не пересобирая образ:

```bash
docker cp app/static/logo.png sport-web-1:/app/app/static/logo.png
```

Так логотип появится сразу, но переживёт только до следующей пересборки —
в репозиторий файл всё равно нужно положить.

## Настройка Telegram

1. Создай бота у [@BotFather](https://t.me/BotFather), получи токен.
2. Узнай свой telegram id у [@userinfobot](https://t.me/userinfobot).
3. Заполни в `.env`:

```
TELEGRAM_BOT_TOKEN=123456:AA...
TELEGRAM_BOT_USERNAME=my_sport_bot     # без @
TEACHER_TELEGRAM_IDS=123456789         # тебе выдастся роль преподавателя
```

Бот работает на long polling — публичный домен и HTTPS не нужны.
Штатный Telegram Login Widget их бы потребовал, поэтому вход сделан через бота:
страница выдаёт одноразовый код, ты отправляешь его боту, страница сама открывается.

`TEACHER_TELEGRAM_IDS` применяется при каждом входе, так что роль преподавателя
нельзя потерять, даже если что-то нажать в интерфейсе.

## Как студент привязывает аккаунт

Портал не просит пароли и токены — только подтверждение, что профиль твой:

1. Студент вводит хэндл на `/accounts` и получает код вида `msu-sport-a1b2c3d4`.
2. Вписывает код в профиль на платформе:
   - **Codeforces** — Settings → Social → поле «Organization» (или «First name»);
   - **LeetCode** — Edit Profile → поле «Name» (или «Summary»/«Website»).
3. Жмёт «Проверить». Портал читает публичный профиль и находит код.
4. После подтверждения код можно убрать.

## Что видно на каждой платформе

| | Codeforces | LeetCode |
|---|---|---|
| API | официальный публичный | неофициальный GraphQL |
| Каталог задач | весь, с рейтингом и тегами | весь, со сложностью и тегами |
| История посылок | полная, включая неудачные попытки | **только последние 20 принятых** |
| Авторизация | не нужна | не нужна |

Полная история LeetCode доступна только по сессионной куке `LEETCODE_SESSION`,
а это фактически полный доступ к аккаунту студента. Сознательно **не** запрашиваем:
для задачи «кто решил назначенное» хватает публичных данных, а хранить чужие
сессии — ответственность, которой лучше не брать.

Практическое следствие: синкер ходит на LeetCode каждые 10 минут, и пока студент
не решает больше 20 задач за этот интервал, ничего не теряется. Неудачные попытки
на LeetCode не видны — аналитика «кто застрял» работает только по Codeforces.

При первой синхронизации Codeforces подтягивается до 3000 последних посылок,
дальше — только свежие.

## Что засчитывается

Решение засчитывается по заданию, только если оно отправлено **после** момента выдачи.
Иначе баллы капали бы за задачи, решённые год назад.

| Статус | Значит | В прогресс | Баллы |
|---|---|---|---|
| `solved_in_time` | решено после выдачи, до дедлайна | да | ×1.0 |
| `solved_late` | решено после дедлайна | да | ×0.5 |
| `solved_before` | решено ещё до выдачи задания | нет | 0 |
| `not_solved` | не решено | нет | 0 |

Задачи, решённые раньше, показываются отдельной отметкой — это полезно знать,
даже если они не приносят баллов. Если нужно засчитать их (например, задание
выдано задним числом), при создании задания есть галочка.

### Баллы

Формула живёт в [`app/services/scoring.py`](app/services/scoring.py) — её точно
захочется крутить по ходу семестра, и это не требует миграций.

- LeetCode: Easy 1, Medium 3, Hard 5.
- Codeforces: `рейтинг / 200` (задача 1600 → 8 баллов).
- После дедлайна — половина.
- Первым решившим в группе — плюс 2.
- Полный комплект по заданию — плюс 5.
- Ивенты считаются отдельно, по своим правилам каждого ивента.

## Как собрать список задач

На странице списка вставь задачи текстом, по одной в строке.
Понимаются вперемешку:

```
https://leetcode.com/problems/two-sum/
two-sum
lc:koko-eating-bananas
https://codeforces.com/problemset/problem/4/A
https://codeforces.com/contest/1352/problem/A
cf:1352G
474B
```

Что не нашлось в каталоге — портал перечислит явно, а не проглотит молча.

## Объявления

Преподаватель публикует анонс на `/teacher/announcements`: заголовок, текст,
ссылка на соревнование, время начала и конца, адресат (весь клуб или одна группа).

Объявления с указанным временем показывают **обратный отсчёт** — он тикает
в браузере, сервер отдаёт только метки времени. Страница `/announcements`
раскладывает их по состояниям: идёт сейчас → скоро → без даты → прошедшие.
Ближайшие два-три висят на главной у студента.

Ссылка проверяется на схему `http`/`https` — `javascript:` в объявление не пройдёт.

Если JavaScript не отработает, вместо таймера останется текст состояния,
посчитанный на сервере.

## Лента решений

Событие в ленте — **первое** принятое решение задачи конкретным студентом.
Перерешивания и повторные отправки не дублируются.

- Студент видит только одногруппников, преподаватель — всех (с фильтром по группе).
- Если задача входит в выданное задание и решена после его выдачи, событие
  подписывается ссылкой на это задание.
- Неудачные попытки в ленту не попадают.

Лента живёт на `/feed`, врезками — на главной у студента и на странице группы
у преподавателя.

## Известные ограничения

- **Вход по коду.** Если студента убедить отправить боту чужой код, чужая вкладка
  войдёт под его аккаунтом. Код живёт 5 минут и одноразовый, бот об этом
  предупреждает. Полностью закрывается переходом на Telegram Login Widget,
  когда появится домен с HTTPS.
- **LeetCode GraphQL неофициальный.** Схема может измениться без предупреждения.
  Клиент переживает 429 и 5xx с ретраями, ошибки синка пишутся в аккаунт и видны
  студенту, но если платформа переименует поле — понадобится правка.
- **Только `leetcode.com`.** `leetcode.cn` — отдельный бэкенд с другими аккаунтами.
- **SQLite.** На группу в сотню студентов запас кратный. Если понадобится больше —
  переезд на Postgres упирается в замену `sqlite_insert(...).on_conflict_do_*`
  в `catalog.py` и `sync.py` на диалект Postgres.
